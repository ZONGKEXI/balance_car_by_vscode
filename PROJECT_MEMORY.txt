> 当前开发策略：暂时不使用 FreeRTOS，采用 **STM32CubeMX + HAL + CMake + 裸机 while(1) + HAL_GetTick() 非阻塞调度**。

## 1. 项目目标

当前项目是 **STM32F103 两轮自平衡小车**。

主要目标：
- 使用 STM32F103 完成底层外设驱动与控制逻辑。
- 使用 TB6612FNG 驱动左右直流电机。
- 后续接入左右编码器、IMU、PID，实现平衡、速度、转向控制。
- 实现电池电压 ADC 采集与电量 LED 指示。
- 使用 USART2 做串口调试。
- 使用 PA11 用户按键控制 TB6612 的 STBY 总使能。
- 后续熟悉后再考虑迁移到 FreeRTOS。

当前推荐开发思路：

```text
CubeMX 配置底层外设
        ↓
HAL 生成 MX_xxx_Init()
        ↓
自定义 app_xxx.c/.h 做应用层封装
        ↓
main.c 中初始化
        ↓
while(1) 中运行非阻塞任务
```

## 4. TB6612FNG 电机驱动

驱动芯片：**TB6612FNG**

关键控制信号：
- STBY
- AIN1 / AIN2 / PWMA
- BIN1 / BIN2 / PWMB

当前理解：

```text
STBY = 0
→ TB6612 待机
→ 电机驱动关闭

STBY = 1
→ TB6612 工作
→ 电机驱动允许输出
```

因此 STBY 可以理解为电机驱动系统的“总闸”。

当前 STM32 映射：

```text
PA1 → TB6612_STBY
```

当前阶段先只实现：

```text
第一次按 PA11
→ STBY = 1
→ TB6612 使能

第二次按 PA11
→ STBY = 0
→ TB6612 待机
```

暂时不急着加入真正的左右 PWM、方向控制和电机转动。

## 5. PA11 USER_KEY 的 CubeMX 配置

PA11 用于读取按钮状态，所以配置为输入：

```text
PA11
→ GPIO_Input
```

推荐：

```text
GPIO mode              Input mode
GPIO Pull-up/Pull-down Pull-up
User Label             USER_KEY
```

逻辑：

```text
未按下 → PA11 = 1
按下   → PA11 = 0
```

HAL 读取：

```c
HAL_GPIO_ReadPin(USER_KEY_GPIO_Port, USER_KEY_Pin)
```

按下判断：

```c
if (HAL_GPIO_ReadPin(USER_KEY_GPIO_Port, USER_KEY_Pin) == GPIO_PIN_RESET)
{
    // 按下
}
```

原因：

```text
USER_KEY → STM32
所以 PA11 是输入
```

## 6. PA1 TB6612_STBY 的 CubeMX 配置

PA1 用于 STM32 主动控制 TB6612，所以配置为输出：

```text
PA1
→ GPIO_Output
```

推荐：

```text
GPIO output level      Low
GPIO mode              Output Push Pull
GPIO Pull-up/Pull-down No pull
Maximum output speed   Low
User Label             TB6612_STBY
```

推荐初始电平为 Low：

```text
PA1 = 0
→ STBY = 0
→ TB6612 上电默认待机
```

CubeMX 重新生成代码后，`main.h` 应有：

```c
#define USER_KEY_Pin GPIO_PIN_11
#define USER_KEY_GPIO_Port GPIOA

#define TB6612_STBY_Pin GPIO_PIN_1
#define TB6612_STBY_GPIO_Port GPIOA
```

注意：
`TB6612_STBY_GPIO_Port` 和 `TB6612_STBY_Pin` 不是在 `app_pwm.c` 里手动定义的，而是 CubeMX 根据 `User Label = TB6612_STBY` 自动生成的宏。

## 7. 教程中的 button / app_button 设计意图

教程将“底层按键检测”和“应用逻辑”分开：

```text

```


```c

```

因此：

```c
if (clicks == 1)
{
    ...
}
```

表示单击事件。

## 8. 教程中的 pwm_on 状态翻转逻辑

教程中：

```c
static uint8_t pwm_on = 0;
```

含义：

```text
0 → 电机驱动待机
1 → 电机驱动活动
```

单击后：

```c
if (pwm_on == 0)
{
    pwm_on = 1;
}
else
{
    pwm_on = 0;
}

App_PWM_Cmd(pwm_on);
```

可以简化为：

```c
pwm_on = !pwm_on;
App_PWM_Cmd(pwm_on);
```

执行效果：

```text
第一次按：
0 → 1 → App_PWM_Cmd(1) → STBY = 1

第二次按：
1 → 0 → App_PWM_Cmd(0) → STBY = 0
```

## 9. app_pwm 当前设计

当前阶段 `app_pwm` 暂时只负责 STBY，不急着加入真正 PWM。

推荐接口：

```c
void App_PWM_Init(void);
void App_PWM_Cmd(uint8_t on);
```

### app_pwm.h

```c
#ifndef __APP_PWM_H
#define __APP_PWM_H

#include "main.h"

void App_PWM_Init(void);
void App_PWM_Cmd(uint8_t on);

#endif
```

### app_pwm.c

```c
#include "app_pwm.h"

void App_PWM_Init(void)
{
    HAL_GPIO_WritePin(
        TB6612_STBY_GPIO_Port,
        TB6612_STBY_Pin,
        GPIO_PIN_RESET
    );
}

void App_PWM_Cmd(uint8_t on)
{
    if (on == 0)
    {
        HAL_GPIO_WritePin(
            TB6612_STBY_GPIO_Port,
            TB6612_STBY_Pin,
            GPIO_PIN_RESET
        );
    }
    else
    {
        HAL_GPIO_WritePin(
            TB6612_STBY_GPIO_Port,
            TB6612_STBY_Pin,
            GPIO_PIN_SET
        );
    }
}
```

对应教程 SPL：

```c
GPIO_WriteBit(GPIOA, GPIO_Pin_1, Bit_RESET);
GPIO_WriteBit(GPIOA, GPIO_Pin_1, Bit_SET);
```

HAL 对应：

```c
HAL_GPIO_WritePin(..., GPIO_PIN_RESET);
HAL_GPIO_WritePin(..., GPIO_PIN_SET);
```

## 11. 电池 ADC 模块

### 原教程链路

```text
TIM2
→ 每 10 ms Update
→ TIM2_TRGO
→ ADC1 Injected Conversion
→ PB0 / ADC1_IN8
→ JDR1
→ JEOC
→ ADC1_2_IRQHandler
```

### 时钟

```text
HSE = 8 MHz
PLL ×9
SYSCLK = 72 MHz
HCLK = 72 MHz

APB1 = /2
PCLK1 = 36 MHz
APB1 Timer Clock = 72 MHz

APB2 = /1
PCLK2 = 72 MHz
ADC Prescaler = /6
ADC Clock = 12 MHz
```

### TIM2

```text
Prescaler = 71
ARR = 9999
Counter Mode = Up
TRGO = Update Event
```

计算：

```text
72 MHz / (71 + 1) = 1 MHz
→ 1 us / count

10000 counts = 10 ms
→ 100 Hz
```

### ADC1 Injected

```text
PB0 → ADC1_IN8

Injected conversions = 1
External Trigger = TIM2 TRGO
Rank 1 = ADC1_IN8
Sampling Time = 1.5 cycles（匹配教程）
```

### HAL 启动

```c
HAL_ADCEx_Calibration_Start(&hadc1);
HAL_ADCEx_InjectedStart_IT(&hadc1);
HAL_TIM_Base_Start(&htim2);
```

### 中断链路

```text
TIM2 Update
→ TIM2_TRGO
→ ADC1 injected conversion
→ JDR1
→ JEOC
→ ADC1_2_IRQn
→ ADC1_2_IRQHandler()
→ HAL_ADC_IRQHandler(&hadc1)
→ HAL_ADCEx_InjectedConvCpltCallback()
```

回调中：

```c
if (hadc->Instance == ADC1)
{
    ...
}
```

表示确认是 ADC1 触发的回调。

## 12. 电池 LED 逻辑

PA4、PA5、PA6：

```text
PA4 → LED1
PA5 → LED2
PA6 → LED3
```

当前电压分级：

```text
vbat > 7.9 V
→ 三灯亮

7.4 < vbat <= 7.9
→ 两灯亮

7.0 < vbat <= 7.4
→ 一灯亮

6.5 < vbat <= 7.0
→ 全灭

vbat <= 6.5
→ 三灯闪烁
```

闪烁采用 `HAL_GetTick()`，非阻塞：

```c
uint32_t now = HAL_GetTick();

if (now - lastTime >= 100)
{
    ...
    lastTime = now;
}
```

不使用：

```c
HAL_Delay(100);
```

## 14. ST-Link 与电池供电现象

已观察：

```text
ST-Link连接 + 小车电源OFF
→ 仍有串口 / 可读电池电压

ST-Link断开 + 电源OFF
→ 无串口

ST-Link断开 + 电源ON
→ 有串口
```

当前判断：
- ST-Link 可以给 MCU 供电。
- 小车电池通过主开关给 MCU 供电。
- 电池 ADC 分压采样点可能位于主开关之前。
- 因此主开关 OFF 时，只要 MCU 仍由 ST-Link 供电，ADC 仍可能读到电池电压。

## 15. USART2

```text
PA2 → USART2_TX
PA3 → USART2_RX
```

CubeMX：

```text
Mode              Asynchronous
Baud Rate         921600
Word Length       8 Bits
Parity            None
Stop Bits         1
Direction         TX/RX
Hardware Flow     None
Oversampling      16
```

USART2 时钟：

```text
PCLK1 = 36 MHz
```

注意：USART2 不像 APB1 Timer 那样获得 ×2 时钟。

HAL 输出：

```c
HAL_UART_Transmit(...)
```

或封装：

```c
My_USART_Printf(&huart2, "BAT = %.3f V\r\n", volt);
```

ARM GCC/newlib-nano 下 `%f` 可能需要额外开启 float printf 支持。

## 16. FreeRTOS 决策

此前尝试过 FreeRTOS，但当前明确决定：

> 暂时不用 FreeRTOS，后续学会后再迁移。

因此当前采用：

```text
裸机
+
HAL_GetTick()
+
while(1)
+
非阻塞任务
```

CubeMX：

```text
FREERTOS = Disable
```

SYS：

```text
Timebase Source = SysTick
```

如果此前为了 FreeRTOS 改为 TIM4，应恢复为 SysTick。

当前主循环思路：

```c
while (1)
{
    App_Bat_LED_Process();
    App_Button_Proc();

    // 后续加入其他低速任务
}
```

真正的平衡控制后续更适合放在固定周期定时器/中断里。

## 18. 软件设计原则

CubeMX/HAL 负责：
- RCC
- GPIO
- ADC
- TIM
- USART
- NVIC

应用层 `app_xxx` 负责：
- 业务逻辑
- 状态管理
- 模块封装
- 对外接口

典型流程：

```text
CubeMX 配置
↓
MX_GPIO_Init()
MX_ADC1_Init()
MX_TIM2_Init()
...
↓
App_xxx_Init()
↓
while(1)
↓
App_xxx_Process()
```
